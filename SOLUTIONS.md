## Задание 1. Размытие изображения

**Что требуется.** В `task_1/blur.py` нужно реализовать `pad_image` и `box_blur`, а затем запустить `task_1/main.py`.

**Идея.** Чёрно-белое изображение — таблица чисел: число в строке `i`, столбце `j` задаёт яркость пикселя. Чтобы усреднить пиксели на краю, вокруг таблицы добавляется рамка ширины `pad`. В режиме `zero` она содержит нули. В режиме `edge` крайние строки и столбцы продолжаются наружу; углы повторяют угловые пиксели. Например, у массива `[[1, 2], [3, 4]]` при `pad=1` и `edge` получится `[[1, 1, 2, 2], [1, 1, 2, 2], [3, 3, 4, 4], [3, 3, 4, 4]]`.

**Как работает код.** `pad_image` создаёт массив большего размера через `np.zeros`, помещает исходный массив в центральный срез и, если выбран `edge`, заполняет полосы повторением крайних пикселей. `box_blur` берёт вокруг каждого пикселя квадрат `kernel_size × kernel_size` и записывает в результат его среднее значение `np.mean`. Размер ядра должен быть нечётным, чтобы у квадрата был центральный пиксель; ширина рамки равна `kernel_size // 2`. Результат создаётся с типом `float`, поскольку среднее может быть дробным. Исходный массив функции не меняют.

**Что показывают изображения.** Первая панель — исходная зашумлённая шахматная картинка. Вторая — усреднение квадратом 3×3 с продолжением краёв. Третья — усреднение квадратом 9×9 с нулевой рамкой. Больший квадрат сильнее сглаживает мелкие детали. Нулевая рамка затемняет края, поскольку в среднее там входят нули.

**Запуск:** из корня репозитория `python task_1/main.py`.

## Задание 2. Метод бисекции

**Что требуется.** Найти корень уравнения `f(x) = 0` на отрезке `[a, b]` с заданной точностью `epsilon`.

**Математическая идея.** Если непрерывная функция имеет на концах отрезка разные знаки, между ними есть хотя бы один корень. Считаем середину `c = (a + b)/2`. Затем оставляем ту половину, на концах которой знаки различаются. После каждого шага отрезок становится вдвое короче. Останавливаемся, если `f(c) = 0`, `|f(c)| < epsilon` или длина текущего отрезка меньше `epsilon`.

**Как работает код.** Функция `bisect` получает саму функцию `f`, концы отрезка и точность. Сначала она проверяет порядок концов, положительность точности и знаки на концах. Если корень уже на конце, сразу возвращает его. В цикле вычисляет середину и значение функции в ней, выбирает левую или правую половину и подсчитывает шаги. Если цикл завершился по длине отрезка, возвращает его середину. Для применимости метода непрерывность функции на выбранном отрезке нужно проверить математически: программа не может доказать её по нескольким вычисленным значениям.

В PDF не задано конкретное уравнение, поэтому `f(x) = x³ − x − 2`, `[1, 2]` и `epsilon = 10⁻⁶` — **демонстрационный пример**. Чтобы решить свой вариант, замените функцию `f` и числа `a`, `b`, `epsilon` в `main`. Для примера `f(1) = −2`, `f(2) = 4`, то есть условие разных знаков выполнено.

**Запуск:** `python task_2/main.py`.

## Задание 3. Двойной маятник

**Что требуется.** Решить уравнения движения двойного маятника из пункта 5.2 PDF, построить траекторию нижнего груза и анимацию. Затем повторить расчёт при изменении начального угла второго стержня на `δ = 10⁻⁶`, сравнить траектории и проверить точность по сохранению энергии.

**Математическая идея.** Положение описывают углы `θ₁`, `θ₂`, а их изменения — угловые скорости `ω₁`, `ω₂`. Поэтому состояние — четыре числа `(θ₁, ω₁, θ₂, ω₂)`. Функция `right_hand_side` вычисляет их производные по формулам (5.5). `solve_ivp` методом `RK45` приближённо находит состояние в 1000 равномерных точках на интервале 0–20 с. Формулы (5.1) переводят углы в координаты грузов: `x₁ = L₁ sin θ₁`, `y₁ = −L₁ cos θ₁`, `x₂ = x₁ + L₂ sin θ₂`, `y₂ = y₁ − L₂ cos θ₂`.

**Как работает код.** `solve` вызывает `solve_ivp` с параметрами из таблицы 1. `coordinates` строит декартовы координаты. `energy` вычисляет `T + V` по формулам (5.2)–(5.3). `make_animation` на каждом кадре обновляет два стержня и уже пройденный след нижнего груза; кадры берутся через каждые пять рассчитанных точек, поэтому анимация длится около 20 секунд при 10 кадрах в секунду. В `main` запускаются случаи A и B с точностью `10⁻⁸`, а также случай A с более грубой точностью `10⁻⁵`.

**Что показывают графики.** `trajectory.png` — путь нижнего груза для случая A; одинаковый масштаб осей не искажает форму. `trajectories_comparison.png` — пути A и B рядом на общих осях: начальные углы отличаются всего на `10⁻⁶` радиана, но к концу движения пути заметно расходятся. `energy_comparison.png` — величина `|E(t) − E(0)| / |E(0)|`: при более точной настройке интегратора энергия сохраняется существенно лучше. Это помогает отличить чувствительность маятника к начальным условиям от ошибки численного решения.

**Запуск:** установите `numpy`, `scipy`, `matplotlib`, затем выполните `python task_3/main.py`. Программа откроет графики и анимацию, а три статичных графика сохранит в `task_3`. Для сохранения анимации как GIF выполните `python task_3/main.py --save-gif` (потребуется `pillow`). Для запуска без окон используйте `python task_3/main.py --no-show`.
